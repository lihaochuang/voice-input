# VoiceInput · 语音输入

按一个键开始说话，再按一下结束，文字直接落在光标处。macOS 与 Windows 都能用。

- 单键热键（默认 macOS 右 ⌥ / 右 ⌘，Windows 右 Alt / 右 Ctrl，**键位可在设置里录制自定义**），按一下开始、再按一下结束，不用按住
- 多个 ASR 后端可配，一个失败自动切下一个（百炼 / Groq / OpenAI / 任意 OpenAI 兼容端点 / 本地 whisper.cpp）
- 长录音自动切片并行转写，产物落成 Markdown
- 热词表、纠错表、历史记录、音频文件导入、文件夹监听
- **自带 Key**：所有识别都走你自己配置的服务，没有任何中间服务器

## 1. 下载哪一个（macOS 按芯片选）

| 你的机器 | 下载 |
|---|---|
| Apple 芯片（M1/M2/M3/M4…） | `VoiceInput-<版本>-mac-arm64.dmg` |
| Intel 芯片的 Mac | `VoiceInput-<版本>-mac-x64.dmg` |
| Windows 10/11（x64） | `VoiceInput-<版本>-win-x64.exe` |

不确定 Mac 是哪种：左上角  → 关于本机，「芯片」写 Apple 就选 arm64，写 Intel 就选 x64。
macOS 没有做 universal 包（两个架构合一个会让体积翻倍），所以选错了只会打不开，换另一个即可。

## 2. macOS 首次使用

**第一次打开要右键 → 打开**（应用只做了本地 ad-hoc 签名，没有买苹果开发者证书，
直接双击会被 Gatekeeper 拦下并说「无法验证开发者」）。

然后要给三个权限，少一个就有一半功能不工作：

| 权限 | 面板路径 | 没给会怎样 |
|---|---|---|
| 麦克风 | 系统设置 → 隐私与安全性 → 麦克风 | 录不到音，托盘显示 🚫 |
| 辅助功能 | 系统设置 → 隐私与安全性 → 辅助功能 | 单键热键用不了，自动降级到组合键；连「录制单键键位」也用不了（设置里点录制会直接提示要权限） |
| 自动化 | 系统设置 → 隐私与安全性 → 自动化 → 允许控制「系统事件」 | 文字只进剪贴板、粘不进光标处 |

自动化那一项的授权弹窗只在**第一次真的要粘贴时**才出现，拒绝过一次就不会再弹，
需要自己去上面那个面板里手动打开。

**还会弹一次钥匙串（Keychain）授权**：应用用系统的 `safeStorage` 加密你的 API Key，
第一次启动时 macOS 会问「VoiceInput 想要使用钥匙串里存储的机密信息」。
点**「始终允许」**。这个弹窗出现期间启动流程是**停住等你回答的**（托盘图标还不会出现），
所以别以为是卡死了。点「拒绝」的话密钥功能会整体禁用（应用会明确告诉你，不会偷偷退化成明文存储）。
换版本后又弹一次是正常的：钥匙串的访问授权绑代码签名，新版本是新的签名。

## 3. Windows 使用说明（先读这一节）

**⚠️ Windows 版未经真机验证。** 全部 Windows 逻辑只靠跨平台构建与代码审查保证，
作者手上只有 macOS。遇到问题照下面自查，并欢迎开 issue。

**单键热键用的是全局键盘钩子（`WH_KEYBOARD_LL`），这和键盘记录器用的是同一个 API。**
Windows Defender 一般直接放行，但公司电脑上的管控软件（深信服、亚信等）可能拦截或告警。
真被拦也不影响使用：到设置 → 热键里切成「组合键模式」，功能一项不缺，只是手感从
「按一下」变成「按组合键」。

最可能遇到的四个问题与自查方法：

| 现象 | 多半是 | 怎么查 |
|---|---|---|
| 不知道有没有在录音 | 托盘图标就是状态指示 | 托盘图标：🎤 待机 / 红点 录音中 / 黄圈 转写中 / 绿勾 已存文件 / 橙三角 出错 |
| 剪贴板里有文字但没插进输入框 | 粘贴用的 PowerShell 宿主没起来 | 看设置 → 关于里的日志，搜「粘贴宿主」 |
| 在某些窗口里粘不进去 | 对方是管理员提权窗口（UIPI 限制） | 这是 Windows 的安全机制，**不绕**；手动 Ctrl+V 即可（文字已在剪贴板） |
| 按单键没反应 | 单键被管控软件拦了 | 设置 → 热键顶部会显示「当前生效：组合键模式」及降级原因 |

## 4. 填 Key

设置 → 后端，主界面只有一个输入框：**粘进去会自动识别是哪家的 Key**。
推荐先用阿里百炼（有免费额度，`qwen3-asr-flash` 中文识别效果好），
控制台链接在界面上。Groq / OpenAI / 任意 OpenAI 兼容端点在「高级设置」里。

两件要知道的事：

- **Key 只存在本机**，用系统的 `safeStorage` 加密后放在 `creds/<后端>.enc`，
  不进 `配置.json`、不进日志、不会上传到任何地方。
- **换电脑要重新填。** 加密绑在当前机器的 Keychain（macOS）/ DPAPI（Windows）上，
  把整个数据目录拷到另一台机器，Key 解不开。解不开时界面会明确说「密钥无法解密，请重新填写」，
  不会假装成「没填过」。

**不内置任何业务术语、不内置任何 Key。** 仓库里的 `热词.示例.txt` / `纠错表.示例.txt`
是通用示例，热词要自己按行业填。

## 5. 几个刻意的取舍（不是 bug）

**① 识别结果会一直留在剪贴板里，不恢复你原来的剪贴板内容。**
这是有意的：粘贴动作可能失败（光标没落在输入框、对方窗口不接受粘贴、提权窗口），
一旦失败，剪贴板里那份就是唯一的找回途径。如果识别完就把原内容恢复回去，
失败时那段话就彻底没了。所以顺序永远是**先写剪贴板，再模拟粘贴**，两件事独立。
代价是你原来复制的东西会被覆盖，重要内容请先粘出去。

**② 口语清理（删掉「嗯/那个/重复的半句」）默认关闭。**
它是拿大模型改写你的原话，实测会删掉有信息量的内容，而且已经加了「必须是原文子序列」
的硬校验仍然挡不住。更要紧的是：会议记录、面试复盘这类场合里，犹豫和重复本身就是材料。
要开就去设置 → 行为里自己打开，知道代价再开。

**③ 长录音占磁盘，但识别成功就删。**
录音期间 PCM 直接落盘（这样进程被杀也不丢音频），16kHz 单声道约 **115MB/小时**，
两小时约 230MB。识别成功后立刻删掉临时音频；失败的那份会留在 `待处理/` 里等自动补转，
补转成功才删。磁盘紧张的话别录超过两小时。

**④ 启动后第一次录音会丢开头约 1.3 秒。**
音频管道是按下热键才建的（刻意如此：不让麦克风从开机起就一直被占用、系统指示灯常亮），
建图实测要 1.3~2.1 秒。想说完整的第一句，先按一次热键空录一下预热；
第二次起管道保持复用，按下即录、不再丢。

**⑤ 离线能力要自己装，而且专业术语会明显比云端差。**
两件事分开说。一是**不开箱**：本应用不随包分发任何离线模型，离线要用就得自己装
whisper.cpp 的二进制和模型（见下一节），这是为了不让安装包为少数人涨几百 MB。
二是**准确率有上限**：离线引擎**不支持热词注入**，所以本应用「把你的专业术语写进热词表、
越用越准」这套机制对它完全不起作用——你那些公司内部的黑话、产品名、人名，
云端百炼能靠热词表纠对，离线跑出来大概率是同音的错别字，而且没法通过配置改善。
建议把离线只当**断网时的兜底**，别当平时主力。

**⑥ 导入音频与文件夹监听的转写不计入历史，也不参与自动热词提炼。**
导入走的是另一条链路，产物只落 Markdown 文件（在你设的转录目录里），不写历史记录。
所以「说得越多、热词越准」那个飞轮只吃热键录音的内容，拿一小时会议录音导进来
不会让热词表自动长出里面的术语——那些词要自己写进热词表。

**⑦ 静音拦截的阈值是按作者这台机器的底噪标定的。**
判据是两条取或：整段峰值 < 200，或者（峰值 < 1200 且最大 200ms 窗 RMS < 120）。
实测这台 MacBook 内置麦：底噪的窗 RMS 在 60~75，轻声说话 496。
换一台机器若底噪明显更高，可能出现「真静音没被拦住」，后果只是多花一次 API 调用；
反之若你说话极轻且环境极安静，仍可能被判静音（托盘会提示「没听到声音」）。
取舍方向是**宁可多花一次请求也不丢话**。

**⑧ 音频图坏掉时会自动重建，最多重建两次。**
一次录音零数据块 → 重建音频图；连续两次 → 重建整个录音组件；
仍失败（连续第三次起）→ 明确提示你退出重开，不再默默重试。
录音时长不足 1 秒的会话不计入这个升级链（手滑点两下不该触发重建）。
刻意**不靠 `AudioContext.state` 判健康**：实测它在渲染器已经送不出数据时仍然报 `running`。

## 6. 离线兜底：本地 whisper.cpp

断网或不想把音频发出去时，可以配本地 whisper.cpp 当后端（也可以当其他后端全挂时的兜底）。
**本应用不随包分发 whisper.cpp 的二进制与模型**（加起来几百 MB，而且大多数人用不到），
需要自己装：

```bash
# macOS
brew install whisper-cpp
# 或自己编译：https://github.com/ggml-org/whisper.cpp

# 下模型（推荐这个：速度与中文准确度的平衡点）
# ggml-large-v3-turbo-q5_0.bin，约 550MB
curl -LO https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo-q5_0.bin
```

然后在设置 → 后端 → 高级设置里，把 whisper.cpp 那一行的「可执行文件路径」和「模型文件路径」
指到上面两个文件，启用它。它不需要任何 Key。

## 7. 数据存在哪

| 内容 | 位置 |
|---|---|
| 配置、热词、纠错表、历史、日志 | macOS `~/Library/Application Support/VoiceInput/`，Windows `%APPDATA%\VoiceInput\` |
| 长录音的 Markdown 产物 | 默认 `文档/语音输入转录/`，可在设置里改 |
| API Key | 上面那个目录的 `creds/*.enc`（系统加密，绑本机） |

**热词表会随每一次识别请求发给你配置的 ASR 服务**，别往里写密码、密钥、金额、证件号。
历史记录里存的是识别原文，想清掉就在设置 → 行为里关掉「记录历史」或改保留天数。

## 9. 自己构建

```bash
npm ci
npm test              # node --test "test/**/*.test.js"
npm start             # 开发态运行
node scripts/make-icons.js   # 重新生成图标（产物已提交，一般不用跑）

npm run dist:mac      # 两个 dmg（x64 / arm64），自动做 ad-hoc 签名
npm run dist:win      # NSIS 安装包，必须在 Windows 上跑（没做 wine 交叉编译）
```

Windows 包由 GitHub Actions 的 `windows-latest` runner 打，见 `.github/workflows/build.yml`。
